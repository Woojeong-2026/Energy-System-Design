1. 파일은 어디에 있고 GitHub와 어떤 관계인가

충전 코드와 검산·학습 자료는 모두 팀 GitHub 저장소에 있습니다. GitHub에서 Markdown 문서를 바로 읽을 수 있습니다. MATLAB 실행에는 저장소를 본인 PC에 clone하거나 Code → Download ZIP으로 받으십시오. 이미 clone한 프로젝트라면 본인 작업을 먼저 저장한 뒤 git pull --ff-only로 업데이트합니다. 별도 검산 패키지를 끼워 넣는 작업은 필요 없습니다.

2. 이 코드의 목적을 한 문장으로 말하기

주어진 탄소 저장률을 만족하는 충전 공정의 정상상태를 구하고, 실제로 회수 가능한 열만 반영하여 필요한 총 전기와 충전 효율을 계산한다.

이 문장에는 네 가지 선택이 들어 있다.

  1. 무엇을 저장하는가: CO₂의 탄소를 고체 C로 저장한다. O₂는 냉각 후 대기로 방출한다.
  2. 무엇을 모델링하는가: 충전 운전의 정상상태다. 기동·정지·열관성·재고 변화의 시간 응답은 계산하지 않는다.
  3. 무엇을 비용으로 세는가: SOEC 전기뿐 아니라 남은 모든 전기가열을 포함한다.
  4. 어떤 열을 쓸 수 있는가: 지정된 경로, 열부하 부호, 온도차 조건을 만족하는 열만 쓴다.

이것은 실제 반응기 체적·셀 면적·열교환기 형상까지 완성하는 상세설계와 다르다. 과제에서 주지 않은 반응속도, 전류밀도, 열전달계수를 임의로 정하지 않았다.

4. 물질수지: 왜 재순환을 먼저 풀었나

SOEC와 반응기 사이에 CO/CO₂가 계속 돈다. 순환되는 양을 정하지 않으면 셀 입력 조성·전압·예열 부하를 정할 수 없다.

기호는 다음과 같다. Faraday 상수와 혼동하지 않도록 신선 공급량은 여기서 f로 쓴다.

  • f: 신선 CO₂ 공급량, 1 kmol/s.
  • X: SOEC 한 번 통과 시 입구 CO₂ 전환율, 0.70.
  • a,b: 셀 입구 CO, CO₂ 몰유량.
  • ξ: 반응기에서 석출되는 탄소 몰유량.
SOEC:     CO₂ → CO + ½O₂
반응기:   2CO → C(s) + CO₂

셀 출구:       CO = a+Xb,       CO₂ = (1−X)b
반응기 출구:   CO = a+Xb−2ξ,    CO₂ = (1−X)b+ξ

전량 재순환·정상상태:
a = a+Xb−2ξ          → Xb=2ξ
b = f+(1−X)b+ξ       → Xb=f+ξ

두 식을 함께 풀면 ξ=f, Xb=2f, b=2f/X.

기준 조건에서 탄소 저장 1 kmol/s, 셀의 CO₂ 전환량 2 kmol/s, 입구 CO₂ 20/7 kmol/s가 된다. 왜 셀에서 2를 전환하는가? 탄소 1을 석출하려면 CO 2가 필요하고, 반응기에서 CO₂ 1이 다시 생겨 순환하기 때문이다. X=0.70은 1회 통과 전환율이며 전체 신선 공급 탄소의 70%만 저장한다는 뜻이 아니다.

이렇게 선형 수지로 미지수를 제거하면 반복 재순환 계산의 초기 추정값·완화계수·수렴 기준에 의존하지 않는다. 주어진 단순 반응·완전 재순환 조건에서 가능한 해석적 단순화다. 퍼지나 부반응을 추가하면 다시 유도해야 한다.

평형식은 어떤 미지수를 추가로 정하나

위 수지만으로 재순환 CO a는 정해지지 않는다. c=b−f를 반응기 출구 CO₂로 두면 평형이 a를 정한다.

ΔG°B = g°C + g°CO2 − 2g°CO
KB = exp(−ΔG°B / RuTB)
KB = (yCO2·P/p°)/(yCO·P/p°)²
   = c(a+c)/(a²·P/p°)
k = KB·P/p°
a = c[1+sqrt(1+4k)]/(2k)       양의 근 선택

순수 흑연의 활동도는 1이고, 기체 몰분율에 고체 탄소를 넣지 않는다. p/p°를 사용하는 이유는 평형상수의 로그 안이 무차원이어야 하기 때문이다. 기준에서 KB≈3.10243, a≈0.535175 kmol/s다.

압력이 오르면 2 mol 기체에서 1 mol 기체와 고체가 되는 석출 방향이 유리해진다. 출구 CO 비율과 충전 순환량이 줄어든다. 다만 평형이 유리하다는 것과 빠르게 반응한다는 것은 다르다. 현재 모델은 반응속도와 체류시간을 검증하지 않는다.

5. 전기화학: 전압, 전류, 열을 분리해 생각하기

전류는 변환 속도, 전압은 전하당 에너지

I = 2·F·(nCO,converted ×1000)
  = 4·F·(nC ×1000)

CO 1 mol당 전자 2 mol, 탄소 1 mol 저장당 전자 4 mol이다. F=96485 C/mol, 유량은 kmol/s이므로 1000 변환이 필요하다. 기준 등가 전류는 385.94 MA다. 이는 전체 활성 셀의 합산 등가 전류다. 실제 직렬 stack의 단자전류와 동일하다고 말하면 안 된다.

가역전압은 반응 Gibbs 에너지와 기체 분압으로 정한다.

Erev = −ΔG°ox/(2F) + RT/(2F)·ln[(pCO/p°)sqrt(pO2/p°)/(pCO2/p°)]
Vch  = Erev + 0.10 V
Wcell = I·Vch

충전은 반응을 역방향으로 밀어야 하므로 손실을 더한다. 산소극은 순수 O₂라 pO₂=P다. 과제 문구에 “inlet”과 스트림 번호가 충돌하지만, 구현은 명시된 5·12번 조성으로 평가한다. 발표에서 이 해석을 명시한다. ΔG를 J/kmol로 받으면 위 식에 넣기 전 J/mol로 바꾸거나 분모에 1000을 포함해야 한다.

왜 전기만 계산하면 안 되나

SOEC를 지정 온도에 유지하려면 에너지수지를 만족하는 열을 추가하거나 빼야 한다.

Qcell = H5+H12−H4−Wcell
Vtn   = (H5+H12−H4)/I
Qcell = I(Vtn−Vch)
  • Erev: 가역 전기화학의 기준 전압, Gibbs 에너지와 관련.
  • Vtn: 이 전력만으로 엔탈피 증가를 공급하는 열중립 전압, 엔탈피와 관련.
  • Vch0, 흡열 운전.
  • Vch>Vtn: 남는 에너지를 빼야 하므로 Qcell<0.

기준에서 Vch≈1.14918 V, Vtn≈1.46210 V라 셀은 약 120.769 MW의 열을 추가로 요구한다. 따라서 셀 소비전력 443.514 MW만을 총 충전 입력이라고 쓰면 안 된다.

6. 열역학: 에너지의 양과 사용할 수 있는 온도는 다르다

엔탈피는 반응열을 이미 포함한다

H=Σnᵢhᵢ(T)이며 Cantera 엔탈피에는 생성엔탈피가 포함된다. 반응 전후 엔탈피 차를 계산한 뒤 ‘반응열’을 별도로 더하면 중복 계산이다. 온도에 따라 cp가 바뀌므로 H(T)를 계산하고 출구 H에서 T를 역산한다. 단위 검산: (kmol/s)×(J/kmol)=J/s=W.

HEX 1은 같은 조성의 현열을 이동시킨다

Qmax = min[Hhot(Th,in)−Hhot(Tc,in), Hcold(Th,in)−Hcold(Tc,in)]
Qhex = εQmax
H8 = H7−Qhex,       H3 = H2+Qhex

반응 전후 서로 다른 조성의 생성엔탈피를 HEX의 회수 가능한 현열로 해석하지 않는다. 향류에서는 저온 입구 쪽 끝에서 같은 위치를 Hcold=H2+q, Hhot=H8+q로 맞춰야 한다. 양 끝 온도만 확인하지 않고 내부 201개 지점의 온도차를 검사한다. 최소 온도차가 작으면 더 촘촘한 확인이 필요하다.

Thermal link는 단순한 열량 차감이 아니다

반응기 Q<0, 셀 Q>0이어도 반응기가 셀보다 20 K 이상 뜨거워야 전달 가능하다. 기준 반응기 650°C, 셀 850°C에서는 열이 있어도 직접 전달할 수 없다. 기본 과제에는 이를 거슬러 올리는 heat pump가 없다. 가능할 때 전달량은 min(0.85|Qdonor|,Qreceiver)다. 나머지는 전기 가열 또는 방출로 처리한다.

본 모델의 85%는 donor의 회수 가능 상한이다. 뽑아낸 열과 받은 열에 다시 별도의 85%를 곱해 이중 손실을 넣지 않는다. 충전 기간의 열을 방전 기간으로 보내는 것도 기본 가정에는 없다.

7. 성능 수치는 어떤 경계에서 계산하나

Pin = Wcell + ΣQel
ηch = nC·LHV_C/Pin
LHV_C = 393.5×10^6 J/kmol

HEX 회수열은 이미 예열 온도와 전기가열 수요를 바꿨다. Pin에서 HEX 열을 한 번 더 빼지 않는다. O₂ 방출과 방출열에는 credit을 주지 않는다. 충전에는 방전 전용 압축기·CO₂ 분리기 전력을 넣지 않는다.

왕복 효율은 시간과 재고를 함께 맞춘다.

nC,ch·tch = nC,dis·tdis
tdis/tch = nC,ch/nC,dis
ηRT = Pout·tdis/(Pin·tch) = ηch·ηdis

단순 Pout/Pin은 유량이 다르면 왕복 효율이 아니다. 같은 탄소 1 kmol당 전기 에너지로 나누면 비교가 명확해진다.

8. 기존 저장소와 새 파일이 연결되는 방식

main.m                           전체 과제 결과와 그림을 재현
  ├─ noon_config()               공통 조건 cfg
  ├─ thermo_init()               공통 물성 객체 th
  └─ run_roundtrip(cfg,th)
       ├─ charging_mode(cfg,th)   충전 결과 R
       │    ├─ thermo/*           h, s, g, 평형, 전압, H↔T
       │    └─ system/*           HEX, link, 결과표
       └─ discharging_mode(...)   방전 결과
            → 같은 탄소 재고 → ηRT

run_charging_review(...)          별도 검산 실행기
  ├─ 위의 charging_mode 호출     팀 통합 main과 같은 함수
  ├─ verify_charging(R,cfg,th)    원시 스트림에서 재검산
  └─ export_charging_json(...)    Python과 비교할 raw.json

cfg는 입력 조건, th는 물성 계산 도구, R은 결과 묶음이다. R.S에는 번호·조성·온도·압력이 있고, R.cell은 전기화학, R.units는 열부하, R.P_in/R.nC/R.eta_ch는 통합용 성능이다. 인터페이스를 유지하면 방전 코드와 main을 광범위하게 고칠 필요가 없다.

9. 검증은 어떤 층으로 이루어졌나

층 질문 방법 통과해도 남는 한계
입력 검사 계산 가능한 조건인가? 유한수·양의 압력·0<X<1 등 유효한 입력이 좋은 설계를 뜻하지 않음
보존법칙 물질·에너지가 사라지지 않았나? 각 장치 C/O/N, ΣHin+Q+W−ΣHout 잘못된 Q를 정의해도 수지는 닫힐 수 있음
구성 법칙 상태가 주어진 물리식을 만족하나? 평형, Faraday, Nernst, HEX·link 조건 평형 도달 속도나 실제 손실은 확인 못 함
다른 구현 한 코드의 구현 오류인가? 해석근 MATLAB vs 이분법 Python 두 구현이 물성·가정을 공유함
오류 주입 검사기가 정말 틀린 것을 잡나? 유량·단위·열회수·전압을 변조 시험하지 않은 모든 오류를 보장하지 않음
실험 검증 실제 장치와 맞나? 실험/문헌의 측정값 대조 현재 과제 자료로는 수행하지 않음

Verification은 모델 식을 코드가 맞게 계산하는지, Validation은 모델이 실제 현상을 얼마나 잘 설명하는지의 문제다. 현재 증거는 주로 전자다. Python self-check를 MATLAB 실행 성공으로 말하면 안 된다. 물성 파일이 같은 두 구현의 일치는 독립 실험 증거도 아니다.

실제로 확인한 것

  • 필수 조건: Python/Cantera 3.0.0의 기준·필수 스윕 9개 저장 케이스, 각 46개 검사 통과. 기준과 P5/T850이 중복되어 서로 다른 조건은 7개다.
  • Python 회귀 시험 8개 method와 내부 subtest 통과.
  • MATLAB 6개 파일의 정적 검사 통과.
  • 학습 자료: 조건 변경 예시 22개를 계산하고 각 46개 검사 통과. 정상 1개+의도적 오류 5개를 계산하여 모두 의도대로 구분.
  • MATLAB 실행과 MATLAB JSON 대조: 아직 미실행. 실제 실행은 본인 MATLAB 환경에서 해야 한다.

특히 중요한 오류 실험

기준에서 온도 조건을 무시해 반응기 열을 셀로 보내고, 가열·방출 양쪽 장부를 함께 수정하면 전체 에너지 잔차는 여전히 거의 0이다. 그런데 계산된 효율은 61.68%에서 약 76.08%로 거짓 상승한다. 불가능한 열전달을 수지만으로는 배제할 수 없기 때문이다.

또 kmol→mol 변환을 빼고, 감소한 전기를 열로 보충하도록 Qcell을 재계산하면 총 입력이 같아질 수도 있다. 그래서 Pin 하나의 일치만으로 코드가 맞다고 판단하지 않는다.

10. 인터랙티브 설명을 학습에 쓰는 순서

인터랙티브 자료를 열고 각 실험에서 클릭하기 전에 결과 방향을 말하고, 값을 바꾼 뒤 이유를 한 문장으로 적는다.

실험 먼저 예측할 것 확인 후 설명할 것
압력 1→10 bar 순환량과 ηch 방향 석출 평형, 예열 수요, 충전·왕복 효율의 차이
셀 온도 750→900°C CO 조성도 바뀔까? 반응기 온도 고정이라 평형은 유지, 열부하는 변화
전압 손실 0.05→0.15 V Wcell과 Pin이 모두 증가할까? 기준 흡열·link off 영역에서는 Wcell 증가만큼 Qcell 감소
반응기 869→870°C 값이 갑자기 바뀌는 이유 20 K on/off 규칙의 수학적 문턱, 실제 장치의 불연속을 입증하는 것은 아님
HEX 유용도 0.75→0.95 어떤 전기가열이 줄어드나? H1, 전체 열수지, 최소 온도차
전환율 0.5→0.9 탄소 저장률도 늘어날까? 고정 신선 공급·무퍼지 정상상태에서는 저장률 고정, 순환량 변화
오류: 온도 조건 무시 수지 검사만으로 잡힐까? 법칙 검사와 수지 검사의 서로 다른 역할

이 예시는 기준조건에서 한 번에 변수 하나를 바꾼 계산이다. 여러 변수의 조합 최적화나 동적 simulation을 보여주는 것은 아니다.

11. 발표 전 스스로 풀어볼 다섯 문제

  1. X=0.70인데 탄소 저장률이 0.70이 아니라 1 kmol/s인 이유를, 식 두 줄로 유도한다.
  2. CO₂ 신선 공급을 2 kmol/s로 하면 전류·전력·효율이 각각 어떻게 바뀌는지 설명한다.
  3. Qcell>0과 Qrx<0의 물리적 뜻과, 왜 둘을 바로 상쇄할 수 없는지 설명한다.
  4. Erev와 Vtn을 서로 다른 물성으로 계산하는 이유를 설명한다.
  5. ‘수지 잔차 0, Python과 일치’를 확인한 뒤에도 실제 반응기 크기를 정할 수 없는 이유를 설명한다.

정답 요지: ①전량 재순환과 Xb=2ξ, Xb=f+ξ ②전류·전력 2배, 이 이상화 모델의 효율 동일 ③가열/냉각 부하와 온도 수준 ④Gibbs vs enthalpy ⑤반응속도·전달·형상·실험 정보가 없음.
